# Boiler Flow Control — v0.3 specification

The controller writes only the boiler flow-temperature number. It does not control gas valves, combustion parameters, pump speed, cylinder thermostat, relay schedules or boiler maximum. Boiler and cylinder limits are authoritative.

1. **Modes:** idle, heating, DHW, mixed DHW/heating, manual hold, off, and no boiler. The physical DHW signal is published independently of the override mode. A positive HW relay signal is immediate. Inference requires a complete, fresh configured zone list, all zero, aggregate ≥90, sustained for two minutes. Short RF gaps have a bounded two-minute grace; relay off plus aggregate <90 ends DHW immediately. Inference cannot reliably distinguish mixed demand without relay evidence.
2. **Heating curve:** `20 + (design_flow − 20) × ((20 − outdoor)/(20 − design_outdoor))^(1/1.3)`, clamped to configured heating bounds. Nonpositive outdoor ratio uses room design temperature before clamping. Defaults remain 55°C design flow, −3°C design outdoor, 35–65°C limits. The flow-temperature approximation is retained pending field calibration.
3. **Demand trim:** maximum zone demand, or aggregate only when no zones are configured, low-pass filtered with a ten-minute time constant. Complete valid demand >70%/<30% for 20 minutes changes the trim ±2 K per ten minutes to ±8 K. Inactive or missing inputs clear sustain timers; inactive correction decays toward zero. Pure heating only; DHW/mixed operation does not train this trim.
4. **Optional room feedback:** select relevant climate entities. Temperature error ≥1 K must persist for ten minutes and average recovery must be below 0.05 K/min before assistance. Additional flow is twice that room's error, bounded to 8 K; the maximum valid room contribution is used. Changes to the room target reset its observation window. When room readings are available this replaces the demand-percentage correction; if none are available, the existing demand correction is used. No room setpoints are changed.
5. **Return optimisation:** return expires after ten minutes and is filtered over three minutes. Only established heating (five minutes) with a fresh active burner/heating signal may accumulate a negative trim. Deadband ±1 K about the configured return objective. Rate 0.2 K/min, elapsed-time capped at two minutes per observation, limit −6 K. First observation establishes the time origin. It recovers when inactive, comfort-limited, or below the deadband; missing/stale return removes the correction. Saturation at the heating floor prevents further negative accumulation. During DHW its time origin advances without training from DHW return. Fresh room error >0.3 K, or filtered demand >70% without valid room feedback, suppresses the applied negative trim.
6. **DHW:** primary target follows cylinder + delta, bounded by DHW limits, and requests at least cylinder target +5 K. Cylinder target defaults to configured 60°C, optionally following a sensor/number or the `temperature` attribute of a climate/water_heater. Missing cylinder temperature uses the configured fallback, defaulting to the existing DHW maximum. No return/cycling temperature penalties. Inadequate temperature progress (<1 K/30 min while below target) or timeout (120 min) latches fallback for the current charge. Missing temperature also immediately uses fallback. A repair issue reports missing data, insufficient progress, timeout or limits that cannot provide completion headroom. Limits are never raised to satisfy headroom. Reset diagnostics begins a new observation window.
7. **Cycling:** record exact off→on transitions, rejecting unknown/unavailable→on. Off transitions record duration when the start was observed. Relay off suggests a requested stop; relay on and actual flow within 1 K of target suggests a possible flow-limit stop; other cases remain uncertain. Publish current modulation, last observed nonzero modulation, actual flow, live setpoint, return and start counts. Three or more starts in ten minutes flags frequent starts. No automatic adjustment is inferred from this flag. Charge-start counts are scoped to the current observed charge.
8. **Freshness and units:** demand/cylinder/room measurements default to 30 minutes, outdoor to 120, current flow and burner/relay evidence for stop diagnosis to five, return to ten. Static setpoints/maxima use numeric validity, not periodic freshness. Reject unavailable/non-finite/out-of-range inputs. Temperatures normalise to Celsius; support Celsius, Fahrenheit and Kelvin, using HA's unit system for climate/water_heater attributes. Demand is expected as 0–100, not an unlabelled fractional load estimate.
9. **Arbitration:** clamp and quantise the requested target to the number's grid, configured regime bounds and live boiler maximum. Round without exceeding the maximum. A contradictory floor/maximum or unavailable configured maximum suspends writes and reports why. Ten-minute target hold, 1 K hysteresis. Bypass for both DHW transitions, changed limits, missing-data/progress fallback and required cylinder completion headroom. Unchanged targets never refresh the target-change timestamp. Reassert the effective target every minute in auto, including the idle curve value.
10. **Readback and overrides:** service completion records the value sent, not physical acknowledgement. Subsequent matching readback confirms it; otherwise show pending, then unconfirmed after three minutes. Failed calls do not advance write memory or consume a mode transition. Manual detection only follows acknowledged output and excludes known dial fallback. Shadow has independent virtual write memory and control state; it obeys the same arbitration without writing. Hold/off suspend writes and accumulation. Entering another override or toggling enable resets adaptation so inactive time cannot count as sustained heating. Settings persist even while the boiler is unavailable.
11. **Upgrade:** v0.2 cycling holds/attempts and potentially inaccurate old write memory are cleared. Existing entities and config keys remain compatible; the retired DHW return-ceiling option is ignored. The reset button preserves its unique ID. Actual curve/live tunable settings are retained. Default startup is shadow unless a previous selection is restored.
12. **Branding and distribution:** local `brand/icon.png` (256×256) and `icon@2x.png` (512×512), original SVG under `assets/`. HACS installs the versioned GitHub release ZIP, with `manifest.json` and all component files at its root. The release version, entity software version and tag agree.

The shared DHW binary sensor allows a companion controller to use the same DHW gate. Actual radiator circulation in mixed operation still requires knowledge of the installation; no room-output or gas-saving claims are inferred from this gate alone. Calibrate against observed room comfort, cylinder completion, gas use and burner durations before changing physical parameters.
